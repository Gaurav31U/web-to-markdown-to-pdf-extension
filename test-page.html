The Architecture of Modern Client-Side Web Applications

As web browsers and rendering engines mature, modern applications increasingly perform complex compilation, conversion, and document synthesis entirely on the user's device. Tasks that once required heavyweight backend clusters—such as parsing arbitrary HTML trees, synthesizing Markdown formatting, and outputting vector PDF files—now execute with sub-millisecond latency within the browser sandbox.

1. Architectural Paradigms: Server vs. Client Processing

Traditional document conversion relied on server-side headless browsers like Puppeteer or Chromium instances running inside Docker containers. While functional, this paradigm suffered from high server maintenance overhead, cold-start latency spikes, and severe data privacy risks, as confidential customer documents had to be transmitted across public network hops.

In contrast, client-side browser extensions operate under the user's direct context. By executing directly in the browser's active tab, extensions like MarkPDF read DOM elements in their rendered state, preserving computed layouts, inline graphics, and authenticated styles without leaking private information.

3. Real-Time Algorithm Implementation

The algorithm identifies candidate boundary boxes using structural AST traversal: 

// Intelligent multi-page pagination algorithm
function paginateDocument(blocks, maxPageHeight) {
  const pages = [];
  let currentPage = [];
  let currentHeight = 0;

  for (const block of blocks) {
    if (currentHeight + block.offsetHeight > maxPageHeight) {
      pages.push(currentPage);
      currentPage = [block];
      currentHeight = block.offsetHeight;
    } else {
      currentPage.push(block);
      currentHeight += block.offsetHeight;
    }
  }
  if (currentPage.length > 0) pages.push(currentPage);
  return pages;
}
